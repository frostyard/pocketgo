# 0073 — Let an agent start its own work session in a fresh worktree with team_work

- **Status:** Accepted
- **Date:** 2026-11-24

## Context

**An agent's own sessions work in its home.** The owner talks to an agent in a session of its profile, which starts in the agent's home ([ADR-0013](0013-load-agent-profiles-from-the-owners-folder-and-route-models-in-code.md)), and a profile with `session: standing` keeps one such session for good ([ADR-0026](0026-keep-the-supervisor-in-one-standing-session-compacted-early-in-code.md)). A session's instructions hold the `AGENTS.md` and the `.pi/skills` of its own folder ([ADR-0043](0043-load-the-global-and-folder-agents-md-and-the-skills-into-every-session.md)), so a session in a home never reads a repository's rules.

**Only the owner and the supervisor start work in a repository.** The owner's New Session starts a session in a new worktree of a profile's checkout, named in code from the request ([ADR-0027](0027-start-the-owners-session-on-a-repository-in-a-new-worktree-named-in-code.md)). The supervisor delegates a thread with `team_delegate`, whose specialist works in a worktree of its own ([ADR-0014](0014-delegate-in-threads-with-team-tools-in-code.md)). An agent in its own session has no way to start work in one of its repositories: it changes the checkout from its home, without that repository's `AGENTS.md`, or asks the owner.

**pi-pocket-team had `team_work`.** An agent in its home opened a linked session of its own in a fresh worktree of one of its repositories, refused a folder that was no git work tree, and refused a call from a linked session ("report the plan to the session that started you"). Each run of the linked session sent its answer to the session that started it. Its home rules told the agent never to change a repository from its home. pocketgo has no such tool (docs/gaps.md, G6).

**What pocketgo has to build it from:**
- A thread's worker sends each run's reply to the session that started it, once, through the outbox (`Server.workerRunEnded`, [ADR-0021](0021-give-a-threads-specialist-a-worker-on-an-api-key-model-in-code.md)).
- A note is a message pocketd owes a session, kept once by its key and placed by the outbox, oldest first per session, counted delivered only once `Engine.Placed` finds it in the transcript ([ADR-0020](0020-plan-before-building-with-the-plan-gate-and-consults-in-code.md)).
- An older session gets a later tool without a new session: at start, or a standing one at its idle refresh ([ADR-0046](0046-let-the-supervisor-read-the-owners-inbox-from-pocketds-records-in-code.md) decision 5).
- A session pocketd starts for the team's work is recorded with `created_by` `team`, and the owner may not rename it ([ADR-0058](0058-rename-a-private-agents-session-from-the-desktop-checked-in-code.md)).

**The owner's request, 2026-11-24,** after reading docs/gaps.md: "strike G1, make a PR for G2, G4, G5, G6, G10, G11 - combine smaller changes into one PR if you can". This is G6.

## Decision

1. **`team_work` is a team tool of an agent's own session** (`roleTools`, `team.MayWork`). A session gets it when its profile is neither a supervisor's nor private, and it works as no thread's specialist, plan lead, cross-review, consult, gather's agent, worker or work session: the owner's own session of an agent or clerk profile, and that profile's standing session. A supervisor delegates with `team_delegate` instead, and a private agent has no team tool ([ADR-0042](0042-give-a-private-agent-its-own-preamble-and-no-team-in-its-sessions.md)). `Server.TeamWork` checks the caller again with its profile as it is now and its role from pocketd's records (`team.CheckWorkCaller`, `Server.sessionRole`): a work session's call is refused with "report to the session that started you", so work sessions do not nest.
2. **Its arguments are checked in code** (`team.CheckWork`, `team.WorkRepository`, `team.WorkTitle`): `repository`, one the caller's profile names, in any case as GitHub compares it, which may be left out when the profile names exactly one; `task`, 1 to 6,000 characters; `title`, at most 120, else the task's first line, as a thread's. A profile no session can start from is refused, as `Server.startable` refuses one: a tool pocketd lacks, no model it runs, or a standing profile's `compactAt` not below the routed model's window (`Server.workChoice`, `profiles.CheckCompactAt`).
3. **Its worktree is named and made in code from the call's key, as an owner's session worktree is** (ADR-0027). The key is the work key, `work:` and the team call's key (`api.TeamCall`). The worktree is `<checkout>--<agent>-<slug>` on the new branch `<agent>/<slug>`, the slug the title's words and the key's suffix (`team.WorkWorktree`, `proto.SessionWorktree`). A checkout that is no git work tree is refused before anything is recorded, and starts nothing. pocketd then records the work by its key (`store.StartWork`); a call run again that finds the work recorded and no session checks its caller and the recorded repository and checkout again before git runs (`Server.recheckWorkCaller`), so a profile that no longer takes the work gets no branch or folder. It binds the branch, path, checkout and real place to the key before git runs (`store.ClaimWorktree`), makes the folder at its real place (`Engine.Real`, `Engine.MakeDir`) and the branch there (`worktree.AddNewKeepingBase`, `worktree.AddNew`'s steps), each step recorded (`store.MarkWorktree`), and checks the worktree again (`worktree.Usable`, `worktree.Marked`) and the profile again, read after the models it is routed among (`Server.recheckWork`), under the lock that orders session starts, right before the session starts. The checks and the creation take the call's own context, so a call stopped before its session exists starts none; only a session PiG created is recorded whatever the call does. The branch starts from a fresh fetch of `origin`'s default branch, as every new worktree's does ([ADR-0056](0056-start-a-new-worktrees-branch-from-a-fresh-fetch-of-the-remotes-default-branch.md)); when the fetch fails and it starts from the checkout's `HEAD`, why is kept with the work's record as soon as the base is decided, before the folder is made (`worktree.AddNewKeepingBase`, `store.KeepWorkStale`), so its task says to fetch and compare, a replayed or recovered one too, since a replay that finds the worktree made decides no base. Each base newly decided replaces what an earlier one kept, a fresh fetch's clearing it.
4. **The work session is a session of the caller's profile, linked to the caller.** It starts at the worktree's real place, on the model `router.Choose` gives any session of the profile, with the profile's tools, lessons and MCP tools ([ADR-0063](0063-connect-a-profiles-mcp-servers-to-its-sessions-with-credentials-pocketd-keeps.md)), titled `<agent name>: <title>` (`team.WorkSessionTitle`). Its instructions hold the worktree's `AGENTS.md` and `.pi/skills` (ADR-0043). It has `team_memory` and `team_watch` ([ADR-0072](0072-watch-a-pull-request-in-code-and-tell-the-session-once.md)), no `team_work`, and no question tool. Its session row is recorded with `created_by` `team`, its link to the calling session in `work_sessions` (work database migration 27), with the model and folder it was created with, and its task note, all in one transaction (`store.RecordWorkSession`). A session the engine made for the key whose record failed is recorded as it was made, without its profile, by the call run again, or by the delivery pass, which records every pending work, one whose session is not recorded yet, that the engine's creation record shows a session for, at the first pass after a start, after a record that failed, and after a create whose answer was lost and whose look at the creation record failed, and creates no session; a pending work a running call holds is looked at again by a later pass (`Server.reconcileWork`); its profile's lessons are then given it by the delivery pass.
5. **The task is the work session's first message, through the outbox.** It is a note keyed by the work key (`team.WorkBrief`): where the session works, on which branch, and that each of its answers goes back to the session that started it. It goes to a watched session, and counts as delivered only once `Engine.Placed` finds it in the transcript. Before each new submission of it, the worktree is checked again, at its place, on its branch, by its mark, as a thread's brief checks its folder (`Server.workTaskCheck`); a task whose worktree is no longer the work's goes to no one, and the calling session is told once (`store.DropWorkTask`, `team.WorkTaskDropped`), by a delivery pass the drop asks for. Until the task is placed or dropped, the work session takes no message from the owner (`409 conflict`), as a thread's specialist before its brief.
6. **Each run of the work session that ends sends its answer to the calling session once** (`Server.workRunEnded`). Runs are read from the work session's cursor exactly as a worker's are (`runReplies`), the cursor the last entry of the last run that ended, never one of a run still at work: a run that ended with the model's final answer sends it, and one that ended otherwise says so. Each is a note to the calling session keyed by the work session and the answer's entry, `[S<id> · work · <title>] <answer>`, clipped to 8,000 characters (`team.WorkReplyText`), kept with the cursor's move in one transaction (`store.QueueWorkReplies`). It is read when the run ends, when the next run starts, at the first delivery pass after a start for every work session, and again by the delivery pass when a read or a write failed. A note's key keeps it once, and the outbox places it once.
7. **The calling session is always there.** pocketd removes no session. While the caller is at work, an answer waits in its queue; one an abort or a failed run withdrew is placed again, as every note is. A calling standing session takes it as it takes a report, with no refresh of its profile first, and so does one whose profile became private: an answer is a message, no team tool.
8. **The tool's answer** names the work session, the model and folder it was created with, kept with the work's record, which no later change of its model touches, so neither a call nor its run again looks anything up after the task went, and none reports a failed start, the worktree's branch, and the prefix its answers carry (`team.WorkStarted`). A call run again after a restart finds the work by its key and answers the same, making no second worktree, session or task. A start whose session pocketd made but could not record answers so, naming the session and telling the caller not to call again, since the delivery pass records it and sends its task (`team.WorkUnrecorded`); one pocketd cannot tell started says that (`team.WorkUncertain`); only one the engine's record shows made nothing is a failure (`team.WorkNotStarted`).
9. **The agent's instructions say where to change a repository.** A session that may call `team_work` at the agent's home has `team.WorkGuide` after its identity: change a repository from a work session, never from the home (`team.WorkGuideFor`). A session the owner opened in a checkout or a worktree (ADR-0027), or on a repository whose checkout is the home too, keeps the tool, and is not told to move its changes: it works where the owner placed it. The tool's description says the rule is a home session's, for an older session's instructions.
10. **An older session gets the tool without a new session:** at start for a session that is not standing (`Server.upgradeWorkTools`, `Engine.SetWorkTool`), and at the idle refresh for a standing one (`Engine.Reconfigure`).
11. **A work session is not renamable:** pocketd started it for the team's work (`team.CheckRename`).
12. **No protocol change.** The work session reaches a client as any session of its profile does, with its title, profile and route. `startedBy` stays a worker's alone ([protocol rule 23a](../specs/protocol.md)). [Protocol rules 10, 25 and 25c](../specs/protocol.md) state the tool and the owner's message before the task.
13. **pocketd never removes a work session's worktree**, as it never removes an owner's session worktree (ADR-0027 decision 6), and its claim stays. [ADR-0054](0054-remove-a-closed-threads-worktree-in-code-with-no-github-write.md) removes a closed thread's worktree alone.

## Consequences

- An agent plans in its own session and starts the repository work where the repository's own rules load, with no owner step, and hears each answer back.
- Work sessions and their worktrees pile up beside the checkouts, with their branches, until the owner removes them. Removing a work session's worktree, as ADR-0054 removes a closed thread's, is a follow-up.
- A work session takes no place on the desk and opens no thread: the supervisor does not see it, and a pull request it opens is linked to no thread, as one an owner's session opens.
- The desktop lists a work session among its agent's sessions, with no line to the session that started it. Drawing that link needs it on the wire, a protocol change, and is a follow-up.
- Every answer of a long work session reaches the calling session, an agent's standing session included, and costs a run of it there.
- An older session that is not standing has the tool after a restart, but not the guide in its instructions; the tool's description carries the rule.
- A known limit, ADR-0027's: a folder swapped for another between the `mkdir` that makes the worktree's folder and the git that fills it cannot be told.

## Alternatives considered

- **The supervisor starts the work as a thread:** the agent would ask the supervisor to delegate to itself, and every answer would go through the desk; the agent that planned the work is the one that hears it back.
- **Name the worktree from a random suffix:** a call run again after a restart would make a second worktree; the call's key names the same one.
- **Send only final answers:** a run the owner aborted, or that failed, would leave the calling session waiting with no word; a worker's runs say so, and so do these.
- **Put the link on the wire as `startedBy`:** the desktop nests only a worker under its starter today, so the link would change nothing it shows, and the protocol would change for it.
- **Remove the worktree when the work session goes idle:** its branch may hold unpushed work or an open pull request; ADR-0054's rules for a closed thread do not carry over without a decision of their own.
